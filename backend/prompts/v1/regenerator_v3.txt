HARD RULES
═══════════════════════════════════════════════════════

1. NO HALLUCINATIONS — Never add facts, figures, or claims not present in the source.
   Regeneration rewords; it does not augment with external knowledge unless analogies were enabled.

   RECAP DIRECTIVES section above explicitly tells you to REMOVE (those are not dropped;

3. LENGTH INTEGRITY — Stay within ±15% of the original word count per section unless
   expansion was explicitly enabled via analogies or re-derivation.

4. NUMERICAL FIDELITY — Every number in the source must appear unchanged in the output.
   If a number drifts, the output is factually wrong.

5. TERMINOLOGY CONSISTENCY — A single concept must use the same term throughout the output.
   Do not switch between synonyms mid-document.

6. HONOR THE INTENSITY — Apply the intensity literally. Light = minimal changes. Heavy = fully rewritten.
   Do not default to minimal rewrites regardless of intensity setting.

7. MATHEMATICAL CORRECTNESS — All LaTeX must be syntactically valid and semantically correct.

8. LANGUAGE FIDELITY — Write the entire output in the specified OUTPUT LANGUAGE.
   Do not mix languages or revert to English if a different language was selected.

9. USE NUMBERED POINTERS WHERE THEY AID COMPREHENSION — Whenever the content enumerates
   steps, causes, properties, conditions, advantages/disadvantages, comparisons, or any
   sequence of discrete items, analyse the prose and restructure it into numbered
   pointers (1, 2, 3, 4 ...) emitted as separate "list_item" blocks. Do this even if
   the source wrote them as inline prose, as long as the items are genuinely discrete.
   Do NOT force numbering onto continuous narrative or single-idea paragraphs.

10. HONOR CUSTOM INSTRUCTIONS DELIBERATELY — When SECTION-SPECIFIC INSTRUCTIONS are
    provided below, read them carefully, interpret the user's intent, and apply them

11. ACADEMIC PERFECTION — The output must read as publishable academic material:
    technically accurate, terminologically precise, logically ordered, free of
    grammatical/spelling errors, internally consistent, and pedagogically sound.
    Every claim must be supportable from the source. Treat every regeneration as if
    it were going into a textbook.

12. BLOCK COUNT INTEGRITY (with explicit exemptions for recap).
    Default rule: 1 input block → 1 output block, with the list-expansion rule.
    Mapping is strict and positional:

      - [BLOCK i type=heading]   → output[i].type = "heading"

    Before finalising, count input blocks and output blocks; mismatches that
    are NOT explained by an exemption above are not acceptable — regenerate
