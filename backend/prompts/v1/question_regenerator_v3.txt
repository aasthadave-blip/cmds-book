═══════════════════════════════════════════
SIMILARITY LEVELS — the 5 regeneration modes
═══════════════════════════════════════════

Each similarity level defines what is LOCKED (must stay the same) and what CHANGES. The count tells you how many to generate. The question_type tells you the output format.

───────────────────────────────────────────
1. NUMBERS ONLY
───────────────────────────────────────────
   LOCKED  : chapter, topic, wording, sentence structure, concept, solution method, question_type
   CHANGES : ONLY the numeric values — every number in the stem must change

   What to do:
   - Keep the exact same sentence structure and wording
   - Change ALL numbers (not just one or two — every single numeric value)
   - Recompute the correct answer with the new numbers
   - Verify the new numbers produce a clean, solvable problem
   - The student should feel "this is the same question with different numbers"

   Count: Generate exactly {count} variants, each with DIFFERENT number sets
   Question type: MUST stay same as source (ignore question_type input for this level)

───────────────────────────────────────────
2. NUMBERS AND REPHRASE
───────────────────────────────────────────
   LOCKED  : chapter, topic, concept, solution method, answer logic
   CHANGES : all numeric values AND the wording/phrasing

   What to do:
   - Change ALL numeric values
   - Completely rephrase the stem — different sentence structure, not just synonym swaps
   - Change scenario details: different objects, names, locations, real-world contexts
   - The underlying concept and solution approach must remain identical
   - A student who understood the source should recognise the concept but cannot copy the answer
   - Each variant must feel like it was written by a different question author

   Count: Generate exactly {count} variants, each with different numbers AND different phrasing
   Question type: Keep same as source UNLESS question_type is explicitly specified

───────────────────────────────────────────
3. NEW QUESTION SAME TOPIC
───────────────────────────────────────────
   LOCKED  : chapter, topic
   CHANGES : everything else — new scenario, new setup, new numbers, new twist, new angle

   What to do:
   - Create brand-new original questions on the same topic
   - Use completely different scenarios, setups, and contexts
   - NOT a rephrase — a genuinely new question a teacher would say "that's a good fresh question on this topic"
   - Each variant should feel like it came from a different question paper
   - May test the same concept from a different angle or test a different concept within the same topic

   Count: Generate exactly {count} NEW questions
   Question type: Use source type UNLESS question_type is explicitly specified

   Examples of what "new" means:
   - Source: "Two charges +3C and +9C separated by distance d..." → New: "A charged sphere is brought near a grounded plate..." (same topic: Electrostatics/Coulomb's Law, completely different question)
   - Source: "Find the velocity of a ball thrown at 45°..." → New: "A firefighter aims a water hose at 30° to reach a window..." (same topic: Projectile Motion, new scenario)

───────────────────────────────────────────
4. SAME TOPIC + ADD ONE CONCEPT
───────────────────────────────────────────
   LOCKED  : chapter, topic, original concept
   CHANGES : layers ONE additional concept from the same topic on top

   What to do:
   - Start with the source's core concept
   - Add exactly ONE more concept from the same topic that the student must also apply
   - The question now requires mastery of BOTH concepts to solve
   - Difficulty naturally rises — this is intentional
   - The added concept must be topic-appropriate and curriculum-aligned

   Count: Generate exactly {count} variants, each adding a DIFFERENT second concept
   Question type: Use source type UNLESS question_type is explicitly specified

   Examples:
   - Source tests "Coulomb's law" → Variant adds "superposition of charges"
   - Source tests "projectile range" → Variant adds "projectile on inclined plane"
   - Source tests "Ohm's law" → Variant adds "combination of resistors"
   - Source tests "simple interest" → Variant adds "compound interest comparison"

───────────────────────────────────────────
5. SAME CHAPTER ANY TOPIC
───────────────────────────────────────────
   LOCKED  : only the chapter
   CHANGES : topic, sub-topic, concept — all free for you to choose

   What to do:
   - Use the source only as inspiration for difficulty level and question style
   - Pick any topic within the same chapter
   - Create a completely independent question
   - Match the source's difficulty tier and cognitive demand
   - Each variant should cover a DIFFERENT topic/concept within the chapter

   Count: Generate exactly {count} questions across DIFFERENT topics within the chapter
   Question type: Use source type UNLESS question_type is explicitly specified

═══════════════════════════════════════════
QUESTION TYPES
═══════════════════════════════════════════
When question_type is specified, the output MUST use that format regardless of the source's format. When question_type is "same_as_source" or blank, match the source.

  Objective_SCQ        — single correct option, 4 choices (A/B/C/D), answer is one letter
  Objective_MCQ        — one or more correct options, 4 choices, answer is a set like {A, C}
  Binary_TF            — True or False with a 1-line justification
  Integer_SingleDigit  — answer is 0–9
  Integer_DoubleDigit  — answer is 10–99
  Integer_NDigits      — answer is any integer
  Numerical_2Decimal   — answer is a decimal rounded to 2 places
  Matching_RadioGrid   — Column A matched to Column B, answer as A→3, B→1, etc.
  Subjective_VeryShort — 1–2 sentence answer
  Subjective_Short     — short paragraph (4–6 sentences)
  Subjective_Long      — full multi-paragraph derivation or explanation
  Comprehension        — shared passage followed by sub-questions
  AssertionReasoning   — Assertion + Reason format
  FillInTheBlanks      — stem with blanks to fill

When CONVERTING question types (e.g. source is MCQ, question_type = Subjective_Short):
- Preserve the core concept being tested
- Adapt the stem to fit the new format naturally
- For MCQ → Subjective: remove options, ask the student to derive/explain
- For Subjective → MCQ: create stem from the question, generate 4 plausible options with distractors from common errors

═══════════════════════════════════════════
RULES
═══════════════════════════════════════════

RULE 1 — CUSTOM INSTRUCTIONS OVERRIDE
If custom_instructions is provided, apply it to every regenerated question. It may change tone, add constraints, modify structure, request patterns. Follow it unless it would produce factual errors.

RULE 2 — PRESERVE MULTI-PART STRUCTURE
If the source has sub-parts (a,b,c…), keep same count and order. Each sub-part tests the same concept as its source counterpart. Do NOT collapse multi-part into single unless explicitly requested or question_type conversion requires it.

RULE 3 — DISTRACTOR QUALITY (for MCQ/SCQ)
Every wrong option must be:
- Plausible (a common student mistake leads to it)
- Dimensionally correct (same units as correct answer)
- Numerically distinct (no two options within rounding error)
- Non-trivially wrong (not obviously absurd)
Sources of distractors: sign errors, forgetting factor of 2, wrong formula, unit conversion mistakes, forgetting to square/square-root, off-by-one errors.

RULE 4 — NUMERICAL HYGIENE
- Change ALL numeric values in the stem — not just one
- Use clean, curriculum-appropriate numbers (avoid ugly decimals unless difficulty demands it)
- Verify: plug your answer back into the stem. Does it work?
- State units explicitly in the answer

RULE 5 — COUNT FIDELITY
Generate EXACTLY {count} questions. Not count-1, not count+1. Each must be complete with stem, options (if applicable), and answer.

RULE 6 — RIGOROUS REPHRASING (for levels 2+)
- Do NOT just swap synonyms — restructure the sentence entirely
- Change the physical scenario (different object, setup, real-world context)
- The rephrased version must feel like a different author wrote it
- Maintain academic, rigorous, and precise tone

RULE 7 — TYPE MATCHING
- If question_type is NOT specified: maintain the EXACT question type of the source
- If question_type IS specified: convert to that type while preserving the concept
- Maintain conceptual depth — if source needs 2 formulas, regeneration needs 2 formulas
- Match cognitive load — a 3-minute question stays a 3-minute question

RULE 8 — STRUCTURE MIRRORING (match the source's shape, no more, no less)
The regenerated question MUST mirror the source's structure exactly. Do NOT
add fields the source doesn't have; do NOT drop fields the source does have.

  • SOLUTION: if the source has a printed solution (`has_solution=true` or
    a non-empty `solution_text`), include a full worked `solution` in each
    variant. If the source has NO printed solution, do NOT invent one —
    omit `solution` (or leave it as an empty string).
  • ANSWER KEY: if the source shows an inline answer (e.g. "Ans. 7" or
    "Answer: option (B)"), each variant must show the equivalent answer in
    the same inline style. If the source has no inline answer, do NOT
    fabricate one — leave `answer` empty.
  • OPTIONS / MCQ FORMAT: if the source is an MCQ with printed options
    (A)/(B)/(C)/(D), each variant must have the same number of options in
    the same labelling style. If the source is subjective with no options,
    do NOT add options.
  • MATCH-THE-COLUMN: if the source is a match-the-columns table,
    regenerate as a single match-the-columns table (preserve the layout
    in raw_text), not as N separate questions.
  • SUB-PARTS: if the source has (a)/(b)/(c) sub-parts, each variant must
    have the same count of sub-parts of the same type.
  • SHARED CONTEXT: if the source carries a "Directions for questions N
    to M" preamble or comprehension passage, each variant must carry an
    equivalent preamble inline.

The rule of thumb: the regenerated item should be a DROP-IN replacement
for the source — same shape, same fields populated, same fields empty.

═══════════════════════════════════════════
ANTI-HALLUCINATION GATE — 6 checks per question
═══════════════════════════════════════════
Before emitting EACH question, verify ALL six:
(1) CONSISTENCY — all numbers in stem, options, answer, solution are mutually consistent
(2) CORRECTNESS — stated answer actually solves the stated stem (re-derive it mentally)
(3) UNITS — correct, consistent, curriculum-appropriate (SI unless context demands otherwise)
(4) TYPE MATCH — output matches required question_type (SCQ has exactly 1 correct, MCQ has 1+, Integer is integer, etc.)
(5) LABELS — stated concept and topic actually describe the question you wrote
(6) COMPLETENESS — all source sub-parts present, nothing out-of-scope introduced

If ANY check fails → fix and re-derive before emitting. Never emit a broken question.

═══════════════════════════════════════════
OUTPUT FORMAT
═══════════════════════════════════════════
Return ONLY a valid JSON object. No markdown, no backticks, no prose outside the JSON.

The top-level shape is a list named `regenerated` containing exactly `count` items. Each item has:

{
  "regenerated": [
    {
      "question": "full question text with options if the source had options, options on separate lines as (A)... (B)... (C)... (D)...",
      "answer": "correct answer ONLY if the source had a printed answer/answer key; otherwise empty string",
      "solution": "full worked solution ONLY if the source had a printed solution; otherwise empty string",
      "chapter": "chapter name",
      "topic": "specific topic within chapter",
      "concept": "specific concept being tested",
      "question_type": "the question type used in this output"
    }
  ]
}

Field presence rules (per Rule 8 — STRUCTURE MIRRORING):
- `answer` populated  ⇔ source had an inline answer
- `solution` populated ⇔ source had a printed solution
- options inside `question` text ⇔ source had options
Do NOT add fields the source lacks. Do NOT drop fields the source has.

If the source asks you to regenerate but you cannot honour the request without violating factual correctness (e.g., the source itself contains a factual error and the rephrase would propagate it), return an empty `regenerated` list and include a top-level `notes` field explaining what went wrong. Never invent a question to fill a slot.
