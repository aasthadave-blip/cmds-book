LAYOUT DETECTION — apply BEFORE you start transcribing each page:

Look at the page geometry and determine the column layout:

- SINGLE-COLUMN: text flows full-width across the page in one top-to-bottom
  stream. Most NCERT textbooks, novels, and standard prose. This is the
  DEFAULT case.
- TWO-COLUMN: page is divided into a left column and a right column,
  separated by a visible gutter. Each column flows top-to-bottom. Common
  in MHT-CET / JEE / NEET prep books, question banks.
- THREE-COLUMN: rare. Three vertical streams side-by-side. Reference
  manuals, dense formula sheets.

For SINGLE-COLUMN pages:
- Use the STANDARD reading order: top-to-bottom, full-width.
- Continue with all the existing transcription rules below.
- Ignore the MULTI-COLUMN block — it does not apply.

For MULTI-COLUMN pages (2 or 3 columns), apply these ADDITIONAL rules
ON TOP OF the standard rules:

READING ORDER:
- READ PER-COLUMN, TOP-TO-BOTTOM. Finish column 1 completely (in printed
  reading order) before moving to column 2. Then column 2 completely
  before column 3. NEVER zig-zag across columns line-by-line.
- An atomic unit (heading + paragraph + key_point + figure + caption) is
  ONE logical block. If a paragraph starts in column 1 bottom and
  continues at column 2 top, treat as ONE paragraph — stitch them
  together in your output.
- A heading that visually spans both columns (a wide bar) introduces
  content below it in BOTH columns. Treat it as a single heading; the
  content under it follows per-column rules.

MATH EXPRESSION INTEGRITY across column wraps:
- All `{` and `}` braces in any math expression MUST balance. Before
  emitting any block, count `{` and `}` in the expression — they MUST
  be equal in count.
- If a math expression starts with `$\int_0^{` in column 1 bottom and

  expression: `$\int_0^{π/2}...$`. Stitch across the column boundary.
- NEVER emit an expression with unmatched braces — re-read the columns
  to find the missing brace before emitting.

LATEX FORMAT — MANDATORY for renderable math (frontend uses KaTeX):
- `equation` block content MUST be valid LaTeX. Use LaTeX commands for symbols — NOT Unicode glyphs in the equation body when a LaTeX command exists:
    fractions:  \frac{a}{b}     (NOT "a/b" inside math)
    sqrt:        \sqrt{x}        (NOT "√x")
    integrals:   \int_{0}^{1}    (NOT "∫")
    sums:        \sum_{i=1}^{n}  (NOT "Σ")
    Greek:       \alpha, \beta, \pi, \theta, \omega, \Delta, \Sigma   (NOT α β π θ ω Δ Σ)
    operators:   \leq, \geq, \neq, \approx, \pm, \times, \cdot   (NOT ≤ ≥ ≠ ≈ ± × ·)
    arrows:      \to, \Rightarrow, \leftrightarrow   (NOT → ⇒ ↔)
    sets:        \in, \subset, \cup, \cap, \mathbb{R}, \mathbb{N}   (NOT ∈ ⊂ ∪ ∩ ℝ ℕ)

- Wrapping: `equation` block content may be either bare LaTeX (`x^2 + y^2 = r^2`) OR wrapped in `$$...$$` / `$...$`. The pipeline normalizes the wrapping. Just emit valid LaTeX inside.
- Inline math in body / key_point / definition content: when you DO embed math inside prose, wrap it with `$...$` (e.g., `"The formula $x^2 = 4$ has two roots"`). PROSE-AS-EQUATION GUARD — DO NOT misclassify English-words sentences as equations:
An English-words sentence with an `=` sign is PROSE, NOT an equation. Examples:
  - "Density = mass / volume"  → emit as `body`, NOT `equation`
  - "Speed = distance / time"  → emit as `body`, NOT `equation`
  - "The mass of a proton = 1.0078 u"  → emit as `body` (value statement)
  - "Binding energy of a nucleus = Δm × 931.5 MeV"  → emit as `body`
Only emit `equation` when the printed line is typeset as a standalone mathematical expression using symbols/variables set apart from prose (e.g., "ρ = m/V", "E = mc²", "x² + y² = r²"). If the line uses full English words for variables OR is a numerical value statement with units, it's `body` text.

CHEMISTRY FORMULAS — MANDATORY use `\ce{...}` (mhchem extension, loaded in KaTeX):
- Wrap EVERY chemistry formula in `\ce{...}` so subscripts/superscripts/bonds render correctly. NEVER write plain "H2O" in chemistry context — write `\ce{H2O}` (renders as H₂O).
    inorganic:     \ce{H2O}, \ce{NaCl}, \ce{H2SO4}, \ce{CO2}
    organic:       \ce{CH3-CH2-OH}, \ce{CH3-CHO}, \ce{C6H6}
    ions:          \ce{Fe^{2+}}, \ce{SO4^{2-}}, \ce{NH4+}
    isotopes:      \ce{^{14}_{6}C}, \ce{^{235}U}
    reactions:     \ce{2H2 + O2 -> 2H2O}, \ce{N2 + 3H2 <=> 2NH3}
    catalysts:     \ce{A ->[catalyst] B}, \ce{A ->[heat] B}
    states:        \ce{H2O(l) -> H2O(g)}
- For chemistry equations: put `\ce{...}` inside an `equation` block content, wrapped as `$$\ce{H2O}$$` or `\ce{H2O}` bare (pipeline normalizes wrapping).
- For inline chemistry in prose (`body`/`definition` content): wrap with `$\ce{...}$`. Example: `"The product is $\ce{H2SO4}$ (sulfuric acid)"`.
- Bond notation: use ASCII bonds `\ce{C-C}` (single), `\ce{C=C}` (double), `\ce{C#C}` (triple). The mhchem extension renders them as proper bond glyphs.
- NEVER use Unicode subscripts (H₂O), Unicode arrows (→), or Unicode bond chars (–, ≡). Always plain ASCII inside `\ce{...}`; mhchem handles rendering.

TABLE CELLS — MATH AND CHEMISTRY MUST RENDER:
The backend converts your `headers`/`rows` arrays into an HTML table where each cell is rendered through KaTeX. So math/chemistry symbols inside ANY cell MUST be wrapped properly, otherwise they render as plain text.
- Math inside a cell: wrap with `$...$`. Example:
    rows: [["Speed of light", "$c$", "$3 \\times 10^8$ m/s"], ["Planck constant", "$h$", "$6.626 \\times 10^{-34}$ J·s"]]
- Chemistry inside a cell: use `$\\ce{...}$`. Example:
    headers: ["Element", "Symbol", "Atomic Number"]
    rows: [["Hydrogen", "$\\ce{H}$", "1"], ["Helium", "$\\ce{He}$", "2"]]
- Fractions, subscripts, superscripts: write as LaTeX inside `$...$`. Example: `"$x^2$"`, `"$\\frac{a}{b}$"`, `"$H_2O$"` (or better: `"$\\ce{H2O}$"`).
- Special symbols (°, ±, ≤, ≥, ×, ÷): wrap as math `"$90°$"`, `"$\\pm 5$"`, `"$x \\leq y$"`, `"$5 \\times 10^3$"`.
- Plain text cells (no math): leave as-is, no wrapping needed. Example: `"Hydrogen"`, `"Solid"`, `"Magnetic"`.
- DO NOT emit complex environments (\\begin{matrix}, \\begin{cases}) inside a cell — keep cell content to single-line inline math.
- DO NOT use Unicode math glyphs (²³⁻⁺×÷≤) inside cells — always use LaTeX `$x^2$` form so KaTeX renders properly.

Why this matters: a cell with `"1.6 × 10^{-19}"` will render as plain text "1.6 × 10^{-19}" (literally the source). A cell with `"$1.6 \\times 10^{-19}$"` renders as 1.6 × 10⁻¹⁹ (rendered math). Always wrap math/symbols.
